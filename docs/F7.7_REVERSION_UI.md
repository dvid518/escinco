# F7.7 — Reversión de cambios de UI

Este documento registra la reversión de los cambios de interfaz de F7.7 que rompieron el layout del dashboard y el modal de edición. Se mantienen únicamente la lógica de subcuentas (M6) y el escritor Node de preferencias.

---

## Motivo

La implementación inicial de F7.7 introdujo un rediseño del dashboard (contenedor separado `#dashboard-instancias`) y del modal de edición (3 secciones nuevas). Esto causó:
- Tarjetas cortadas y superpuestas en el grid.
- Botones flotando fuera de su posición.
- Modal sin las secciones correctas.

El dashboard en producción (último commit `faa0543`) funciona correctamente. El alcance real de F7.7 era solo: funcionamiento correcto de subcuentas (M6 desbloqueado) + escritor Node de preferencias. No debía rediseñar el dashboard ni el modal.

---

## Qué se revirtió

### `css/dashboard.css`
Se eliminó el bloque `.dashboard-instancias`, `.dashboard-instancias-titulo` y `.dashboard-instancias-grid` (48 líneas). El dashboard vuelve a usar exclusivamente el grid `.dashboard` principal con `repeat(auto-fill, minmax(260px, 1fr))`.

### `dashboard.html` / `demo.html`
Se restauró la plantilla `tpl-dashboard-editor` a sus 2 secciones originales:
1. Cards regulares (`.editor-grid-esqueleto`)
2. Cuentas y activos (`.editor-pills-cuentas`)

Se eliminó la 3ª sección (`.editor-pills-activos`). Los templates de ambos archivos quedan idénticos, como exige `tests/plantillas.test.mjs`.

### `js/pages/dashboard.js` — UI revertida
Se eliminaron:
- Contenedor `#dashboard-instancias` del `render()` (div `.dashboard-instancias` con `.dashboard-instancias-grid`).
- Función `montarCardsInstanciadas()` restaurada para montar en `.dashboard` directamente (sin grupo separado).
- Función `ordenarInstanciasDashboard()`.
- Funciones `moverInstanciaDashboard()` y `reordenarInstanciasPreferencias()`.
- Chequeo `esCardInstancia(id)` en `moverCardDashboard()`.
- Función `configurarEventosReordenamientoInstancias()`.
- Variable `sortableInstanciasDashboard` y función `inicializarSortableInstancias()`.
- Llamadas a `ordenarInstanciasDashboard()` en `reordenarDashboard()`.
- Llamadas a `inicializarSortableInstancias()` en `inicializarSortableDashboard()`.
- Destrucción de `sortableInstanciasDashboard` en `desactivarEdicionCardsDashboard()` y `render()`.
- `activarModoEdicionDashboard()` / `salirModoEdicionDashboard()` restaurados a un solo `.dashboard` (no `querySelectorAll(".dashboard")`).
- Función `renderizarPills()` restaurada a una sola función que renderiza cuentas y activos juntos en `.editor-pills-cuentas` (se eliminaron `renderizarPillsCuentas()` y `renderizarPillsActivos()`).

---

## Qué se mantuvo

### `js/pages/dashboard.js` — lógica de subcuentas (M6)
- `entidadDeInstancia(id)`: acepta cuentas hijas (ya no las rechaza con `esHija()`), desbloqueando M6 para que cada subcuenta sea una instancia individual.
- `pintarCardCuenta()`: muestra `saldoInicial` propio de la cuenta en lugar de `saldoFamilia()` (agregado familiar).
- `clampDimensionesDashboard()`: fuerza 1×1 para instancias `cuenta:`/`activo:` (no redimensionables).
- Import eliminada: `saldoFamilia` ya no se importa desde `familiaCuentas.js`.

### `scripts/migraciones/aplicar-preferencias.mjs` (NUEVO)
Escritor Node de preferencias M6-M8:
- Lee `propuesta-m6.json`, `propuesta-m7.json`, `propuesta-m8.json`.
- Aplica solo propuestas con `estado_general === "aprobada"`.
- Escribe `preferencias.dashboard` (cardsVisibles, orden, dimensiones) y nombres de subcuentas (M8).
- Idempotente: verifica estado actual antes de escribir.
- `--dry-run` obligatorio para no escribir.
- Rollback: guarda estado previo en `reporte-preferencias.json`.
- Transportes: `memoria`, `archivo`, `rest`.
- `node --check` pasa.

## Pendiente
