### 6.4 Análisis del stack trace
El error ocurre durante la evaluación del módulo ESM cuando el loader detecta una cadena `https://`. El stack trace interno de Node.js apunta a `node:internal/modules/esm/load`, indicando que el loader está procesando el código fuente en búsqueda de esquemas de URL.

### 6.5 Posible explicación
Aunque las correcciones movieron todas las constantes `https://` de módulo-level a dentro de funciones, el loader ESM de Node.js v26.13.0 puede estar realizando un **análisis estático preliminar** sobre todo el código fuente antes de la ejecución, detectando cualquier cadena `https://` independientemente de su posición en el código. Esto explicaría por qué el error persiste incluso después de mover las constantes.

Oppure, puede que el grafo de imports del test incluya módulos externos (node_modules o firebase) que sí tengan URLs `https://` en sus fuentes, y el loader las esté procesando como parte de la carga del módulo padre.

| Hecho | Evidencia |

| El error persiste en Node v26.13.0 y reportedly en Node 22 LTS | Confirmación del usuario |

### 8.2 Causalidad probable (Evidencia C - Limitación de Entorno)
**El error ESM `Only URLs with a scheme in: file and data` persiste a pesar de eliminar todos los `https://` del código propio del proyecto, porque:**

1. **Node.js v26.13.0 loader ESM agresivo**: La versión v26 puede realizar análisis estático sobre todo el código fuente cargado, identificando cadenas `https://` anywhere en los archivos, no solo en módulo-level. Esto es un cambio de comportamiento respecto a versiones LTS (20/22) o el loader tiene una sensibilidad diferente.

2. **Cadena de imports incluye módulos con URLs reales**: Aunque el código propio ya no tiene `https://` en módulo-level, el **grafo de imports completo** incluye:
   - `tests/f7CalculoPatrimonio.test.mjs`
   - `→ import PatrimonioServicio.js`
   - `→ import DivisaServicio.js` (ahora sin módulo-level https://, pero...)
   - `→ import firebase/firestore.js` (el paquete firebase podría tener URLs `https://` en sus fuentes o en `package.json` origins)
   - `→ import "../core/familiaCuentas.js"`, etc.

3. **El loader procesa todo el grafo**: Cuando el loader evalúa `PatrimonioServicio.js`, también carga y evalúa todas sus dependencias transitivas. Si alguna de esas dependencias (incluso paquetes node_modules o firebase) contiene `https://` en su fuente, el loader podría marcar el módulo padre como inválido.

### 8.3 ¿Por qué f7ModeloDatos.test.mjs pasa?
Porque **no importa DivisaServicio.js ni ningún módulo con URLs `https://`** en su cadena de dependencias. Sus imports son solo `Posicion.js` y `PosicionRepositorio.js`, que no tienen URLs `https://` en su código.
