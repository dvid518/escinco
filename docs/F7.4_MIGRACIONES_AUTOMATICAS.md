## 2. Migración M1: Padre con saldo propio

### 1.1. Objetivo
Detectar cuentas con `esAbstracta: true` y `saldoInicial != 0`, y migrarlas:
- Crear cuenta(s) regular o subcuenta(s) con el saldo del padre
- Vaciar `saldoInicial` a 0 en el padre
- Marcar `migradoM1: true` en el padre

### 1.2. Cuándo aplicar
- Cuentas con `esAbstracta === true` y `saldoInicial != 0`
- Padres que tienen saldo propio pero eran abstractos (sin clase activa)

### 1.3. Script: `scripts/migraciones/m1-padre-saldo.mjs`

#### Parámetros:
- `--dry-run`: muestra qué haría sin aplicar cambios (por defecto)
- Sin `--dry-run`: aplica la migración (con backup previo automático)

#### Flujo:
1. Cargar todas las cuentas de la base de datos
2. Filtrar: `esAbstracta === true && saldoInicial != 0 && !migradoM1`
3. Para cada cuenta candidata:
   - Si `tipo` es broker o exchange: crear cuenta regular independiente con el saldo
   - Si no (padre abstracto simple): crear subcuenta con el saldo
   - Establecer `saldoInicial = 0` en el padre
   - Establecer `migradoM1: true` en el padre
4. Guardar backup antes de aplicar cambios

#### Ejemplo dry-run:
```
=== Migración M1: Padre con saldo propio ===

Total de cuentas cargadas: 15
Candidatas a migrar: 3

> Migrando cuenta padre c1: saldo=100, tipo=banco
   [DRY-RUN] Crearía cuenta regular con saldo 100
   [DRY-RUN] Vaciaría saldoInicial a 0 en padre c1
   [DRY-RUN] Marcaría migradoM1: true en c1

> Migrando cuenta padre c2: saldo=500, tipo=broker
   [DRY-RUN] Crearía cuenta regular independiente con saldo 500
   [DRY-RUN] Vaciaría saldoInicial a 0 en padre c2
   [DRY-RUN] Marcaría migradoM1: true en c2

> Migrando cuenta padre c5: saldo=200, tipo=exchange (multidivisa)
   [DRY-RUN] Crearía subcuentas PEN y USD con saldos 200/convertidos
   [DRY-RUN] Vaciaría saldoInicial a 0 en padre c5
   [DRY-RUN] Marcaría migradoM1: true en c5

⚠ Ejecutado en modo DRY-RUN. No se persisten cambios.
   Usa el script sin --dry-run para aplicar de verdad (con backup previo)
```

### 1.4. Idempotencia
- Si `migradoM1 === true` en la cuenta, la migración se salta automáticamente
- No hay riesgo de migrar dos veces la misma cuenta

#### Tests M1:
- Padre con saldo → se migra, saldo transferido, padre vacío
- Padre sin saldo → se salta, sin cambios
- Padre ya migrado → se salta, sin cambios
- Padre archivado → se salta (política propia o filtro adicional)

## 2. Migración M2: Subcuentas monetarias

### 2.1. Objetivo
Detectar padres multidivisa que no tienen subcuentas por divisa y crear
las subcuentas faltantes con `saldoInicial: 0`.

### 2.2. Cuándo aplicar
- Padres con múltiples divisas (PEN, USD, USDT) sin estructura de subcuentas
- La estructura de subcuentas ya existe parcialmente (algunas divisas tienen subcuenta, otras no)

### 2.2. Script: `scripts/migraciones/m2-subcuentas.mjs`

#### Parámetros:
- `--dry-run`: muestra qué haría sin aplicar (por defecto)

#### Flujo:
1. Cargar todos los padres de la base de datos
2. Filtrar: padres con `esAbstracta === false` y `tipo ∈ {broker, exchange}`
3. Para cada padre candidata:
   - Identificar las divisas base (PEN, USD, USDT)
   - Verificar qué divisas ya tienen subcuenta
   - Crear subcuentas faltantes con `saldoInicial: 0`
   - No modificar saldos existentes

#### Ejemplo dry-run:
```
=== Migración M2: Subcuentas monetarias ===

Total de padres cargados: 8
Con divisas multiples: 3

> Padre p1 (broker): divisas PEN, USD
   [DRY-RUN] Ya tiene subcuentas para las 2 divisas → saltando

> Padre p2 (broker): divisas PEN, USD, USDT
   [DRY-RUN] Faltan subcuenta USDT → crearía subcuenta USDT con saldoInicial: 0
   [DRY-RUN] Subcuenta PEN ya existe → no hace nada

> Padre p3 (exchange): divisas PEN, USD
   [DRY-RUN] No es candidato M2 (tipo=exchange sin saldo activo), saltando

⚠ Ejecutado en modo DRY-RUN. No se persisten cambios.
   Usa el script sin --dry-run para aplicar de verdad (con backup previo)
```

### 2.4. Idempotencia
- Si el padre ya tiene subcuentas para todas las divisas base, la migración se salta
- Solo crea subcuentas verdaderamente faltantes

#### Tests M2:
- Padre con 1 divisa → no es multidivisa, se salta
- Padre con N divisas (2-3) y sin subcuentas → se crean subcuentas faltantes
- Padre con N divisas y subcuentas parciales → se crean solo las faltantes
- Padre ya completo → se salta sin cambios

## 3. Migración M3: Brokers multidivisa

### 3.1. Objetivo
Detectar brokers con efectivo en varias divisas y organizar la estructura
del efectivo del broker, creando subcuentas por divisa si aplica.

### 3.2. Cuándo aplicar
- Brokers con `tipo === "broker"` y efectivo en múltiples divisas
- Efectivo que debería distribuirse en subcuentas por divisa

### 3.3. Script: `scripts/migraciones/m3-brokers.mjs`

#### Parámetros:
- `--dry-run`: muestra qué haría sin aplicar (por defecto)

#### Flujo:
1. Cargar todos los brokers de la base de datos
2. Filtrar: `tipo === "broker"` y `saldoInicial != 0`
3. Para cada broker candidata:
   - Verificar si ya tiene subcuentas organizadas
   - Si no, organizar el efectivo en subcuentas por divisa
   - No duplicar el saldo total (repartir o mantener en subcuenta principal)

#### Ejemplo dry-run:
```
=== Migración M3: Brokers multidivisa ===

Total de brokers cargados: 5
Candidatos a migrar: 2

> Broker b1 (broker): efectivo en PEN, USD
   [DRY-RUN] Crearía subcuenta PEN con saldo preservado
   [DRY-RUN] Crearía subcuenta USD con saldo preservado
   [DRY-RUN] Mantenería total efectivo = saldoInicial original

> Broker b2 (exchange): efectivo en USD solo
   [DRY-RUN] No es broker → saltando

> Broker b3 (broker): ya tiene subcuentas organizadas
   [DRY-RUN] Ya migrado M3 → saltando

⚠ Ejecutado en modo DRY-RUN. No se persisten cambios.
   Usa el script sin --dry-run para aplicar de verdad (con backup previo)
```

### 2.5. Idempotencia
- Si el broker ya tiene subcuentas (de una migración M3 previa), se salta
- Si el broker no tiene efectivo en múltiples divisas, se salta

#### Tests M3:
- Broker 1 divisa → no es multidivisa, se salta
- Broker N divisas (2-3) sin subcuentas → se organiza efectivo por divisa
- Broker ya migrado M3 → se salta sin cambios
- Broker sin efectivo → se salta sin cambios
