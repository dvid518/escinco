# F7.3_DIAGNOSTICO_ESM.md — Diagnóstico issue de tests ESM + HTTPS

## 1. Reproducción del error

Ejecución: `cd C:\Users\david\Downloads\David\prog\escinco\tests && node run.mjs f7CalculoPatrimonio`

Errores capturados:

```
=== f7CalculoPatrimonio.test.mjs ===
  !! excepcion no controlada: Unexpected token 'export'

=== f7Indicadores.test.mjs ===
  !! excepcion no controlada: Only URLs with a scheme in: file and data are supported by the default ESM loader. Received protocol 'https:'
```

## 2. Análisis del runner de tests

Archivo: `tests/run.mjs`
- Uso: `await import(pathToFileURL(join(AQUI, archivo)).href)`
- Convierte rutas absolutas a URLs `file://`
- Carga módulos ESM dinámicamente con `import()`

## 3. Raíz del problema: `DivisaServicio.js` línea 190

Archivo: `js/services/DivisaServicio.js`

```javascript
const API_TIPO_CAMBIO = "https://open.er-api.com/v6/latest/USD"
```

**Este `const` de nivel de módulo con una URL `https://` es evaluado por el loader ESM de Node.js durante la carga del módulo.** El loader intenta procesar el esquema `https:` y lo rechaza, lanzando el error:

> "Only URLs with a scheme in: file and data are supported by the default ESM loader. Received protocol 'https:'"

**Cadena de imports que desencadena el error:**

```
run.mjs
  └─ import test file (f7CalculoPatrimonio.test.mjs)
       └─ import * as patrimonioServicio from "../js/services/PatrimonioServicio.js"
            └─ import { convertirMonto } from "./DivisaServicio.js"
                 └─ const API_TIPO_CAMBIO = "https://open.er-api.com/v6/latest/USD"  ← ERROR
```

## 4. ¿Por qué los tests F7.2 pasan?

`f7ModeloDatos.test.mjs` importa `js/models/Posicion.js` y `js/repositories/PosicionRepositorio.js`. Estos módulos no importan `DivisaServicio.js`, por lo que la cadena de imports nunca llega al archivo con la URL `https:`.

## 5. Opciones de corrección

| Opción | Descripción | Impacto en lógica |
|--------|-------------|-------------------|
| **A: Mover constante a función** (recomendada) | Mover `const API_TIPO_CAMBIO = "https://open.er-api.com/v6/latest/USD"` dentro de `actualizarTipoCambioAuto()` como constante local. No cambia comportamiento, solo evita que el ESM loader procese la URL en tiempo de módulo. | Ninguno - la función sigue usando la misma URL en `fetch()` |
| **B: Eliminar la constante** | Remover `API_TIPO_CAMBIO` y usar la URL directamente en `fetch()`. | Ninguno - mismo efecto, pero menos consistente con estilo del código |
| **C: Configurar runner de tests** | Añadir `NODE_OPTIONS=--experimental-vm-modules` o similar. | Requiere cambiar entorno; no es portable |
| **D: Mockear import** | Usar `vi.mock()` o similar en el test. | Cambia estructura de tests; overhead mayor |

**Opción A elegida:** Mover constante a función - es la corrección mínima, no altera lógica de negocio y resuelve el issue de raíz.

## 6. Corrección aplicada

### Archivo modificado: `js/services/DivisaServicio.js`

**Antes (línea 190, nivel de módulo):**
```javascript
const API_TIPO_CAMBIO = "https://open.er-api.com/v6/latest/USD"
const TIEMPO_MAXIMO_API = 10000

export async function actualizarTipoCambioAuto(uid) {
    const controlador = new AbortController()
    const temporizador = setTimeout(() => controlador.abort(), TIEMPO_MAXIMO_API)

    try {
        const respuesta = await fetch(API_TIPO_CAMBIO, { signal: controlador.signal })
        // ... resto de la función
```

**Después (dentro de la función, nivel local):**
```javascript
export async function actualizarTipoCambioAuto(uid) {
    const API_TIPO_CAMBIO = "https://open.er-api.com/v6/latest/USD"
    const TIEMPO_MAXIMO_API = 10000
    const controlador = new AbortController()
    const temporizador = setTimeout(() => controlador.abort(), TIEMPO_MAXIMO_API)

    try {
        const respuesta = await fetch(API_TIPO_CAMBIO, { signal: controlador.signal })
        // ... resto de la función, sin cambios
```

**Cambio:** La constante `API_TIPO_CAMBIO` ya no está en nivel de módulo; es una constante local dentro de `actualizarTipoCambioAuto()`. Esto evita que el ESM loader de Node procese la URL `https:` durante la carga del módulo, mientras se conserva exactamente el mismo comportamiento en tiempo de ejecución (la función `fetch` sigue recibiendo la misma URL).
