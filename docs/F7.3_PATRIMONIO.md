# F7.3_PATRIMONIO.md — Patrimonio: Fuente Única de Verdad

## 1. Propósito

Implementar `calcularPatrimonio()` como **única fuente de verdad** para el cálculo del patrimonio del usuario, reemplazando la lógica fragmentada anterior en `SnapshotServicio.js` y `ContextoServicio.repartirPorDivisa()`. Este módulo (`js/services/PatrimonioServicio.js`) garantiza:

- **Efectivo y posiciones computados de forma independiente** sin duplicación contable.
- **Filtros explícitos** por `custodioId` y `esPatrimonio/Abstracta`.
- **Indicadores derivados** (`cuentasFinancieras`, `custodios`, `subcuentasMonetarias`, `posiciones`, `activosDistintos`).
- **Transacción atómica** en futuras fases (F7.4–F7.6) para movimiento + efectivo + posición.
- **Compatibilidad** con datos legacy (posiciones sin `custodioId`) marcadas como `pendiente_asignacion` hasta M5.

## 2. Nueva función `calcularPatrimonio({incluirPosiciones})`

### 2.1 Firmas y flujo

```javascript
import { calcularPatrimonio } from "../js/services/PatrimonioServicio.js"

// Uso típico:
const stats = await calcularPatrimonio({ incluirPosiciones: true })
```

### 2.2 Filtres independientes

| Categoría | Filtro aplicado | Qué incluye | Qué excluye |
|-----------|----------------|-------------|-------------|
| **Efectivo patrimonial** | `esPatrimonio !== false && esAbstracta !== true && tipo !== "exchange"` | Cuentas normales, broker, subcuentas | Pestañas cripto (`esPatrimonio: false`), padres abstractos, exchange directo |
| **Posiciones patrimoniales** | `custodioId !== null` (asignadas) | Posiciones con dueño conocido (broker/exchange) | Legacy (`custodioId === null`) — van en M5 |
| **Deudas tarjetas** | `tipo === "credito"` | Deuda de tarjetas de crédito | Demás tipos de cuenta |

### 2.3 Retorno del objeto

```javascript
{
  // Efectivo (liquidez + inmovil)
  liquidezPEN, liquidezUSD,
  inmovilPEN, inmovilUSD,

  // Posiciones (solo asignadas)
  inversionesPEN, inversionesUSD,

  // Desglose por divisa (PEN, USD, USDT)
  porDivisa: { pen, usd, usdt },

  // Totales agregados
  totalActivos,        // efectivo + posiciones
  totalDeudaPEN, totalDeudaUSD, // deudas de tarjetas
  totalCuentas,        // cuentas efectivas (filtradas)
  patrimonioPEN,       // efectivo + posiciones - deudas (PEN)
  patrimonioUSD,       // idem (USD)
  patrimonioUSD,       // alias
  patrimonioUSDT,      // idem (USDT)
  tieneDeuda: boolean
}
```

### 2.4 Lógica de filtros (código)

```javascript
function filtrarEfectivoPatrimonial(cuentas) {
    return cuentas.filter(c => {
        if (c.estado === "archivada") return false
        if (c.esAbstracta === true) return false
        if (c.esPatrimonio === false) return false
        if (c.tipo === "exchange") return false  // exchange directo no cuenta efectivo
        return true  // broker, subcuentas, cuentas simples entran
    })
}

function filtrarPosicionesPatrimoniales(posiciones) {
    return posiciones.filter(p => p.custodioId !== null) // legacy excluido
}
```

## 3. Indicadores derivados

`obtenerIndicadoresPatrimonio()` retorna un objeto independiente con cinco conteos:

| Indicador | Significado | Cálculo |
|-----------|-------------|---------|
| `cuentasFinancieras` | Cuentas "reales" (banco/broker, sin subcuentas, sin exchange) | `tipo ∈ {banco, broker} && padreId === null && tipo !== "exchange"` |
| `custodios` | Cuentas con tipo broker/exchange y estado activa | `tipo ∈ {broker, exchange} && estado === "activa"` |
| `subcuentasMonetarias` | Cuentas con padreId definido | `padreId !== null` |
| `posiciones` | Posiciones asignadas (custodioId !== null) | `p.custodioId !== null` |
| `activosDistintos` | Activos únicos en posiciones asignadas | `new Set(posiciones.map(p => p.activoId)).size` |

## 4. Transacción Atómica (F7.4–F7.6)

El flujo de compra/venta en `MovimientoServicio.js` será refactorizado para usar `writeBatch` o `runTransaction` de Firestore, de modo que las tres escrituras (movimiento + efectivo + posición) ocurran en una sola transacción:

1. **Lectura** del estado actual (cuenta de efectivo + posición)
2. **Validación** de disponibilidad, existencia de cuenta, custodio válido
3. ** Escritura atómica** de los tres documentos en un solo lote
4. **Reintentos idempotentes**: si falla a mitad, no se duplica el efecto; el batch se reintenta o se revierte

**Objetivo:** Que un error en la actualización de la posición **nunca** deje el efectivo descontado ni inconsistente. El usuario ve una operación fallida atómica, no un estado parcial.

## 5. Migración de datos (F7.4–F7.6)

- **M4:** Posiciones legacy (`custodioId: null`) → asignación manual o automática por símbolo; marcan `pendiente_asignacion`.
- **M5:** Después de migradas, `calcularPatrimonio` incluye todas las posiciones; `pendiente_asignacion` desaparece.
- **Sin cambios en datos en F7.3:** Solo lecturas con filtros; los datos legacy siguen viviendo sin ser tocados.

## 6. Compatibilidad hacia abajo

- `SnapshotServicio.js` sigue funcionando llamando a `calcularPatrimonio()` internamente, pero quedará en modo sololectura; los nuevos desarrollos deben usar `PatrimonioServicio.js`.
- `ContextoServicio.repartirPorDivisa()` puede continuar usándose para resúmenes de texto, pero sus cálculos quedan obsoletos frente a `calcularPatrimonio()`.
- No se rompe nada en UI o reglas Firestore; solo se añade un nuevo servicio de lectura.

## 7. Casos de prueba (F7.3)

| Código | Escenario | Resultado esperado |
|--------|-----------|------------------|
| **D1** | Cuenta simple PEN/USD/EUR con saldo | `patrimonioPEN` = saldo, `totalCuentas` = 1, sin posiciones |
| **D2** | Contenedor + N instancias | `totalCuentas` = N (solo instancias), contenedor abstracto excluido |
| **D3** | Padre legacy con saldo + hijas | Si no migrado (M1): saldo fuera del cálculo; si migrado: suma correcta |
| **D4** | `esPatrimonio: false` en cuenta | Queda excluida de `efectivo`; sus posiciones (if any) entran por filtro de `custodioId` |
| **D5** | Posición sin custodio vs. con custodio | `custodioId === null` → sin patrimonio; `custodioId !== null` → cuenta en inversiones |
| **D13** | Broker con efectivo + posiciones | `liquidez` incluye saldo broker; `inversiones` incluye posiciones; **ningún bloque se duplica** |
| **D14** | Transacción atómica fallida | Si falla la posición, el efectivo no se mueve; batch revierte consistencia |
| **D15** | Migración M4: pestaña cripto + posición | Una sola fuente: pestañas excluidas del efectivo; posiciones vía `custodioId`; sin conflicto |
