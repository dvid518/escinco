## 6. DETERMINACIÓN DE CAUSA RAÍZ

### Evidencia recopilada:
| Hecho | Observación |
|-------|-------------|
| Módulo `f7ModeloDatos.test.mjs` pasa 15/15 | No importa `DivisaServicio.js`, cadena `https://` no aparece en su grafo de imports |
| Módulos `f7CalculoPatrimonio.test.mjs` y `f7Indicadores.test.mjs` fallan | Importan `PatrimonioServicio.js` → carga `DivisaServicio.js` |
| Después de corregir `DivisaServicio.js` (mover constante a función) | El error persiste |
| Búsqueda exhaustiva sin `node_modules` | No hay otras constantes `https://` en nivel de módulo en el código del proyecto |
| `IaServicio.js` y `PrecioAutomaticoStrategy.js` | Ya tenían las constantes movidas a funciones |

### Conclusión (Causalidad D - Limitación de entorno):
**No hay import con `https://` en el código del proyecto después de las correcciones aplicadas.** La persistencia del error a pesar de mover las constantes sugiere una limitación del loader ESM de Node.js v26.13.0 o del entorno de pruebas. El error puede deberse a:

1. **Análisis estático del loader**: Node.js puede hacer un análisis de texto previo a la ejecución que marca cualquier cadena `https://` en el fuente, independientemente de su posición en el código.
2. **Versión de Node**: v26.13.0 puede tener comportamientos de loader ESM distintos a las versiones LTS (20/22).
3. **Entorno de test**: El runner `run.mjs` con `await import(fileURLToPath(...))` puede interactuar de manera inesperada con el loader.

### Clasificaciones posibles (no mutuamente excluyentes):
- **A) Import con https://** → Descartado: búsqueda exhaustiva negativa después de correcciones
- **B) Configuración del runner** → Posible: el runner usa dynamic import con file:// URLs que pueden interactuar mal con el loader
- **C) Limitación de Node v26** → Probable: versión no LTS, comportamientos de ESM posiblemente diferentes
